# 3DGeoGon Embedding Reference

This file records how the 3DGeoGon website resource is meant to be embedded after upload.

## Files To Publish

Upload the whole `3DGeoGon/` folder from the website file resource. These files must stay together because the app uses relative paths:

- `index.html`
- `app.js`
- `style.css`
- `3DGeoGon-embed.js`
- `tripatterson-embed.js` (migration-edition redirect only; new pages must use `3DGeoGon-embed.js`)
- `legacy-route-redirects.apache.conf` (server configuration example; do not serve it as content)
- `manifest.json`
- `build/`
- `images/`

The packaged upload artifact is:

```text
website-file-resource/3DGeoGon-website-file-resource.zip
```

## Migration Compatibility

For this edition, `3DGeoGon-embed.js` also recognizes the legacy embed class and data attribute. The small legacy-named loader redirects an old loader filename only when the request already reaches the current published folder. JavaScript cannot repair an old directory or differently-cased URL that the server returns as `404`; install equivalent server redirects first. `legacy-route-redirects.apache.conf` is a ready-to-adapt Apache example.

The app also performs a rollback-safe browser autosave migration. Values count as valid only when they contain at least one known restorable primitive slot; an object-kind name alone is not enough because constructions depend on primitive points. When both current and legacy saves are valid and both have timestamps, the newest `savedAt` value wins; ties or missing timestamps deterministically prefer the current key. Corrupt or unknown-content values never displace a valid save.

Introduced in `0.2.1` and retained in `0.2.10`, the rollback window writes the selected save to both the current and legacy keys. New saves, deletes, and restore-suppression signatures are also mirrored so temporarily rolling back the app cannot expose stale or resurrected state. Retire this dual-write only in a later, explicitly announced edition.

The web app manifest now uses the fully renamed `3dgeogon-3d-geometry-canvas` identity. Browsers can therefore treat this edition as a separate installed PWA; remove the superseded installed app and install 3DGeoGon again if both appear. The redirect and compatibility selectors can be retired only after published embeds, server routes, and saved browser state have been migrated and verified.

The packaged web route remains case-sensitive `/3DGeoGon/` even though the local source repository uses lowercase directory names. If the deployed route is intentionally changed to `/3dgeogon/`, update every absolute example below and reverse the redirect targets in the supplied server configuration.

## Standard Script Embed

1. Open 3DGeoGon.
2. Build the diagram.
3. Click `EMBED SCRIPT`.
4. Paste the generated snippet into the page where the diagram should appear.

The snippet has this shape:

```html
<div class="threedgeogon-embed" data-state="PASTE_GENERATED_STATE_HERE" data-height="540" data-title="3DGeoGon diagram" data-autofit="1" data-zoom="1"></div>
<script src="3DGeoGon-embed.js?v=2026080901" defer></script>
```

If the script is not in the same folder as the page, use the full path:

```html
<script src="/3DGeoGon/3DGeoGon-embed.js?v=2026080901" defer></script>
```

The script creates an iframe pointed at:

```text
/3DGeoGon/index.html?v=2026080901&embed=1&autofit=1&zoom=1#state=...
```

The `v=2026080901` entry-document token prevents a browser from reusing an older `index.html` after a release changes bundled asset paths. The loader replaces any existing `v` parameter supplied through `data-src`. `embed=1` puts the app into canvas-only mode, hiding the title screen, side panel, and empty-state text.

## Direct Iframe Embed

If script tags are blocked by the website editor, use an iframe directly:

```html
<iframe
  src="/3DGeoGon/index.html?v=2026080901&embed=1&autofit=1&zoom=1#state=PASTE_GENERATED_STATE_HERE"
  title="3DGeoGon diagram"
  style="display:block;width:100%;height:540px;border:0;background:#fff;"
  allowfullscreen
></iframe>
```

## Embed Attributes

The script reads these optional attributes from the `.threedgeogon-embed` element:

| Attribute | Purpose | Example |
| --- | --- | --- |
| `data-state` | Required encoded diagram state generated by `EMBED SCRIPT`. | `data-state="g.H4sI..."` |
| `data-height` | Iframe height. Plain numbers are treated as pixels. | `data-height="620"` |
| `data-width` | Iframe width. Defaults to `100%`. | `data-width="100%"` |
| `data-title` | Iframe accessibility title. | `data-title="Unit 3 pyramid diagram"` |
| `data-src` | Alternate credential-free HTTP(S) path to `index.html`, including a trusted cross-origin host. `javascript:`, `data:`, `file:`, and credentialed URLs are rejected. | `data-src="/3DGeoGon/index.html"` |
| `data-vars` | Optional label token values. Labels containing `{a}` use the matching value. | `data-vars="a={a};b={b}"` |
| `data-autofit` | Set to `0` to keep the iframe size fixed instead of fitting to visible content. | `data-autofit="0"` |
| `data-zoom` | Set to `0` to disable wheel and pinch zoom inside the iframe while keeping rotation available. Website embeds default to `1`; Moodle filter embeds default to `0`. | `data-zoom="0"` |

## JSON Workflow

Use `EXPORT JSON` when the diagram should be stored as an editable source file. Use `IMPORT JSON` to reload it later.

Use `COPY JSON` when a website, LMS, or notes file needs the raw JSON in the clipboard.

The JSON export contains metadata plus the internal `snapshot` object. Future app versions should keep importing both:

- Full 3DGeoGon export JSON with a `snapshot` field.
- Raw snapshot JSON with `version`, `composite`, and `objects`.

## Image Workflow

Use `EXPORT PNG` for a static image of the current canvas view. This is useful when an interactive embed is not appropriate or when a worksheet needs a fixed diagram.

PNG export captures the current camera angle, visible labels, objects, grid/theme state, and canvas background.

Use `EXPORT SVG` for a true vector SVG file from the current camera view. The export projects 3DGeoGon geometry into SVG elements such as `<polygon>`, `<line>`, `<path>`, `<circle>`, and `<text>`. It crops the SVG to the visible object bounds so empty viewport space is not included.

Use `COPY SVG HTML` when the Moodle editor accepts pasted HTML. It copies inline SVG markup shaped like this:

```html
<svg width="640" height="480" xmlns="http://www.w3.org/2000/svg" xmlns:svg="http://www.w3.org/2000/svg" viewBox="0 0 640 480" role="img" aria-label="3DGeoGon viewport image">
  <!-- Created with 3DGeoGon true vector SVG export -->
  <g class="layer">
    <title>Layer 1</title>
    <polygon points="..." fill="#7db3e8" fill-opacity="0.14" stroke="none"/>
    <line x1="..." y1="..." x2="..." y2="..." stroke="#000000"/>
    <path d="M..." fill="none" stroke="#000000"/>
    <text x="..." y="...">A</text>
  </g>
</svg>
```

For Moodle, the practical order is:

1. Set the camera/view so the object is visible.
2. Turn labels, grid, theme, and point markers on or off as needed.
3. Use `EXPORT SVG` for a downloadable image file, or `COPY SVG HTML` for pasteable HTML.
4. If Moodle strips inline SVG, use `EXPORT PNG` instead.

## Maintenance Notes

- Keep all embed paths relative where possible so the folder can move between sites.
- Rebuild deterministically with `node scripts/package-website-resource.mjs` after changing `index.html`, `app.js`, `style.css`, either embed loader, `manifest.json`, `build/`, `images/`, or this document.
- Run `node scripts/package-website-resource.mjs --verify-only` to compare canonical sources with both the staged folder and ZIP without rebuilding.
- After rebuilding, test the packaged folder, not only the source folder.
- A valid embed test should confirm that the iframe URL includes `v=2026080901` and `embed=1`, the diagram state loads, and the side panel is hidden.
- If a site strips script tags, use the direct iframe form.
- If a site has a strict Content Security Policy, it must allow iframes/scripts from the folder or domain hosting 3DGeoGon.
